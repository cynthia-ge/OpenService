# OpenService architecture

OpenService is a Java 27 / Spring Boot 4.1.2 application with server-rendered Thymeleaf views and CSS. UI and HTTP API entry points share the same validation, workflow and JDBC storage services. No JavaScript frontend build is required.

`Application.java` starts the server or invokes the private credential setup command. `Store.java` manages PostgreSQL/SQLite connections, schema bootstrap and initial administrator creation. `Migrations.java` serializes startup upgrades and journals ordered schema changes. `Service.java` implements accounts, queries, aggregates, records, workflows and imports. `WebController.java` owns HTTP authentication, CSRF, sessions, attachments and views. `Passwords.java` creates PBKDF2 hashes and verifies existing PBKDF2 and scrypt hashes. `Invitations.java` and `RecoveryLinks.java` implement hashed, expiring one-time links; `SecurityEvents.java` records committed account lifecycle changes. `SessionLifetime.java` enforces the absolute browser-session age. `catalog.json` supplies initial table/workflow metadata.

The existing `os_schema`, `os_user`, `os_record`, `os_event` and `os_attachment` tables and JSON record values remain compatible. Each request uses its own connection; mutations commit atomically and failures roll back. PostgreSQL row locks and optional revision ETags protect updates. Attachments (maximum 5 MB each) live in the database. Ordered transactional migrations preserve existing accounts, credentials and records. Startup is serialized on both databases; unsupported or inconsistent migration history prevents startup. Back up the database and use planned downtime before replacing a deployment; rolling upgrades and operational restore targets remain unverified.

Deployment uses PostgreSQL; SQLite is also supported for development. Both database paths run the same HTTP acceptance and workflow tests. Credentials in an existing database continue to work; changing ADMIN_PASSWORD does not reset an existing account. Sessions are server-side and bind to stable, generated user IDs and a persistent authentication revision; self-service revocation changes that revision and is enforced on the next request. Account state, role/password changes and recovery also invalidate sessions. Browser authentication lasts at most eight hours; the servlet idle timeout is 30 minutes. Pre-upgrade sessions without an authentication timestamp must sign in again. The current-account API exposes only ID, name and role.

This is a single-tenant foundation. Local roles authorize action categories. Administrators can restrict a record to one stable user ID or group and administrators; record reads, counts, exports, notes and attachments follow that policy. Field-level ACLs remain unavailable. Audit history survives deletion. SSO, granular ACLs, background workers and distributed operation remain future work.

Docker runs the executable JAR as UID 10001. Compose publishes loopback HTTP with secure cookies disabled only for that local demo; Terraform retains HTTPS deployment configurations. The application has no third-party browser scripts, telemetry or AI-provider dependency. Terraform configurations are independent cloud roots, not automatic failover.

`os_invitation`, `os_recovery` and `os_security_event` are local platform tables, separate from business-record audit. Invitation and recovery tokens contain 192 random bits and persist only as SHA-256 digests. Acceptance uses a shared PostgreSQL administrative transaction lock (SQLite uses IMMEDIATE transactions) and account-row locks where credentials may change concurrently. Links are relative, responses are no-store/no-referrer, and password/token material never enters security-event details. Manual sharing and external recipient verification are explicit limitations; no email delivery worker exists.

Password authentication uses a separate short transaction phase before business routing. Its persistent, bounded attempt counters commit on success/failure, so a business rollback cannot erase failed authentication evidence. The PostgreSQL authentication advisory lock is released before record/account mutations. Browser session authentication does not run password verification or reset counters.

`Configuration.java` validates and atomically promotes versioned definitions in the existing `os_schema` store. `TypedFields.java` supplies shared validation, reference integrity, assignment eligibility and state-entry policies. PostgreSQL HTTP mutations acquire a shared advisory lock before record/account routing; SQLite retains IMMEDIATE write transactions. This serializes configuration promotion and record/reference mutations. The JSON package format and constraints are documented in [configuration](configuration.md).

`Analytics.java` streams numeric values from the complete authorization-filtered record selection and accumulates exact decimal totals per group. It is shared by the local analytics API and server-rendered reporting workspace. It does not reuse the capped Table API page or cast decimals to floating-point database aggregates.
